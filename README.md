# Ticket Hunter (رجا)

رصد خودکار سایت [رجا](https://raja.ir) و پیش‌بردن خرید بلیت قطار **تا درگاه بانک**.
به‌محض پیدا شدن بلیت مطابق فیلترهای شما، ربات مسافران را وارد می‌کند، به صفحه‌ی
پرداخت می‌رسد و با پیامک خبرتان می‌کند تا خودتان پرداخت را تمام کنید.

> ربات **هرگز پرداخت نمی‌کند** و **کپچا را حل نمی‌کند**؛ روی صفحه‌ی درگاه می‌ایستد
> و منتظر شما می‌ماند.

## امکانات

- رصد هم‌زمان چند تاریخ و مسیر با فاصله‌ی زمانی تصادفی (jitter) و backoff روی خطا
- فیلتر و اولویت‌بندی نتایج (قیمت، ساعت، نوع سالن، ظرفیت)
- پر کردن خودکار فرم مسافر و بررسی مقادیر قبل از رفتن به پرداخت
- اطلاع‌رسانی پیامکی از طریق ملی پیامک
- داشبورد فارسی (RTL) با نمای زنده‌ی مرورگر؛ پرداخت و کپچا هم داخل همین نما انجام می‌شود
- ذخیره‌ی همه‌چیز در SQLite و ادامه‌ی خودکار رصدها پس از راه‌اندازی دوباره

## پیش‌نیاز

- Node.js 20 یا بالاتر
- یک حساب کاربری در رجا
- (اختیاری) حساب ملی پیامک برای اطلاع‌رسانی

## راه‌اندازی

```bash
npm install            # Chromium مربوط به Playwright هم نصب می‌شود
npm run build          # ساخت داشبورد
npm start              # http://127.0.0.1:4317
```

پس از باز شدن داشبورد، حساب رجا، ملی پیامک و حالت مرورگر را در صفحه‌ی
**تنظیمات** ثبت کنید. اطلاعات در SQLite محلی (`data/`) ذخیره می‌شود و هرگز
لاگ یا در پاسخ API نمایش داده نمی‌شود.

فایل `.env` فقط برای گزینه‌های راه‌اندازی سرور (مثل `PORT`) است و اختیاری؛
نمونه‌اش در `.env.example` هست.

## توسعه

```bash
npm run dev            # سرور
npm run web:dev        # داشبورد روی پورت 5317 با پراکسی به سرور
npm run dev:login      # تست ورود به رجا
npm run dev:search     # تست جستجو و پارس نتایج
npm run dev:sms        # تست پیامک
npm run typecheck
npm test
```

## معماری

```
src/
  raja/      ← هر چیزی که با سایت رجا حرف می‌زند (Playwright)
  hunter/    ← زمان‌بندی، فیلتر، اولویت‌بندی، حلقه‌ی اصلی رصد
  notify/    ← ملی پیامک
  server/    ← Fastify: REST + WebSocket + سرو داشبورد
  db/        ← SQLite (better-sqlite3)
  utils/     ← تاریخ شمسی، ارقام فارسی، لاگر
web/         ← داشبورد React + Vite
data/        ← دیتابیس، پروفایل مرورگر، اسکرین‌شات‌ها (در گیت نیست)
```

سایت رجا payload درخواست‌ها را سمت کلاینت رمز می‌کند، بنابراین همه‌چیز داخل یک
مرورگر واقعی (Playwright) اجرا می‌شود. تمام سلکتورهای DOM فقط در
`src/raja/selectors.ts` هستند؛ اگر ظاهر سایت عوض شد، فقط همان فایل باید اصلاح شود.

جزئیات کامل رفتار سایت، تله‌های فرم‌ها و درس‌های آزمایش زنده در
[CLAUDE.md](CLAUDE.md) آمده است.

## نکات استفاده

- رجا با درخواست‌های پشت‌سرهم خطای «خطا در اتصال سرویس» می‌دهد. تاریخ‌های زیاد با
  فاصله‌ی کوتاه رصد را عملاً خفه می‌کند؛ اگر نتایج مدام خالی است، اول تعداد
  تاریخ‌ها را کم کنید یا فاصله را بیشتر کنید.
- اگر برنامه ناگهانی بسته شود، قفل پروفایل کروم جا می‌ماند؛ برنامه در اجرای بعد
  خودش آن را پاک می‌کند.

## خط قرمزها

- کپچا حل نمی‌شود؛ ربات متوقف می‌شود، پیامک می‌دهد و منتظر کاربر می‌ماند.
- پرداخت انجام نمی‌شود؛ ربات دقیقاً روی صفحه‌ی درگاه بانک می‌ایستد.
- استفاده از این ابزار با مسئولیت خود شماست؛ با سایت محترمانه رفتار کنید (یک
  نشست، فاصله‌ی معقول بین درخواست‌ها).
